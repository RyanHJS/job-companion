# Resume Text Snapshot

Use this structure for both `resume-current.md` and `resume-proposed.md`. Keep
the document complete and normalized so a Git-style diff shows only resume
wording changes. Preserve section order, role chronology, dates, titles,
locations, bullets, and skills. Do not include review commentary in a snapshot.

```markdown
# Resume

## Header

Name and contact links as represented in the source resume.

## Experience

### Employer | Role | Dates | Location

- Resume bullet text.

## Education

### Institution | Degree | Dates | Location

## Technical Skills

- Category: skills
```

The current snapshot is source-faithful. The proposed snapshot may change only
in-scope proposal text. Keep inferred or invented wording marked in the
adjacent proposal records until the user confirms it.
